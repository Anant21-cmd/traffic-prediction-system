# AI-Based Traffic Prediction System

A full-stack web app that predicts traffic congestion — **Low / Medium / High** — from
current road conditions, using a **Decision Tree Classifier** trained on historical-style
traffic data.

Built with **React** (frontend), **Flask** (backend API), and **Scikit-learn** (AI/ML).

## 2. Quick Start

### Backend (Flask API — runs on `http://localhost:5000`)

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

# Optional — only needed if you want to regenerate data / retrain from scratch:
python generate_dataset.py
python train_model.py

python app.py
```

Leave this running. Check it worked: open `http://localhost:5000/health` in a browser —
you should see `{"status": "Backend is running", "model_loaded": true}`.

### Frontend (React — runs on `http://localhost:3000`)

Open a **second terminal**:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:3000` in your browser. The sidebar shows a green "Backend
connected" dot once it can reach the Flask API.

## 3. How It Works (Architecture)

```
 React (frontend)  --HTTP/JSON-->  Flask (backend)  --uses-->  Decision Tree pipeline (.pkl)
        |                                |                              |
   fills a form                   validates input              predicts Low/Medium/High
   shows the result                stores prediction                + confidence
        |                          in SQLite (history)
        <----------- JSON result -------|
```

1. The user fills in the Traffic Prediction form (vehicle count, time, day, weather,
   location, previous traffic).
2. React sends that as JSON to `POST /predict` on the Flask backend.
3. Flask validates the input, builds a one-row table from it, and passes it through the
   **saved Scikit-learn pipeline** (preprocessing + Decision Tree together).
4. The pipeline returns a predicted class and a probability for each class.
5. Flask saves the prediction to a local SQLite database (`predictions.db`, created
   automatically) and returns the result as JSON.
6. React displays the traffic level, confidence, a probability breakdown, and a
   simplified explanation — and the Dashboard/History pages read back from
   `GET /history` to show live stats and charts.

## 4. API Documentation

Base URL: `http://localhost:5000`

### `GET /health`
Returns whether the server (and trained model) is up.
```json
{ "status": "Backend is running", "model_loaded": true }
```

### `GET /model-info`
Returns the algorithm, feature list, and the saved evaluation metrics (accuracy,
precision, recall, F1, confusion matrix).

### `POST /predict`
**Request body:**
```json
{
  "vehicle_count": 200,
  "hour": 8,
  "day_of_week": "Monday",
  "weather": "Rainy",
  "location": "Main Road",
  "previous_traffic": "Medium"
}
```
**Response:**
```json
{
  "prediction": "Medium",
  "confidence": 0.556,
  "probabilities": { "Low": 0.0, "Medium": 0.556, "High": 0.444 },
  "explanation": [
    "Vehicle count (200) is moderate for this road",
    "The selected time falls within typical peak commute hours",
    "Rainy weather tends to increase congestion",
    "The previous recorded traffic level was Medium"
  ],
  "input_summary": { "...": "the request you sent, echoed back" }
}
```
Returns `400` with an `{"error": "..."}` body for invalid input (e.g. `hour` outside
0–23), and `503` if no trained model is loaded on the server.

### `GET /history`
Returns every stored prediction, newest first.

### `DELETE /history`
Clears all stored predictions.

## 5. The Dataset

Real historical traffic-sensor data isn't available for a student project, so
`generate_dataset.py` builds a **realistic synthetic dataset**: 3,000 records where
vehicle counts, peak hours, weekends, weather, and the previous traffic reading combine
into a "congestion score", which is then split into Low/Medium/High. The patterns are
genuine and learnable — for example:

- Weekday rush hours (7–9 AM, 5–8 PM) push vehicle counts and congestion up
- Weekends are generally lighter
- Rain and storms increase congestion
- A High previous reading makes a High current reading somewhat more likely

A little random noise is mixed in on purpose, so classes overlap slightly at the edges —
just like real traffic — instead of producing a suspiciously perfect 100%-accuracy model.

## 6. Model Training

`train_model.py`:
1. Loads `data/traffic_data.csv`
2. Splits into features (`X`) and target (`y = traffic_level`)
3. One-hot encodes the categorical columns (day, weather, location, previous traffic)
   inside a `Pipeline`, so the exact same encoding is reapplied automatically at
   prediction time
4. Splits 80% train / 20% test (stratified, so all 3 classes are represented in both)
5. Trains a `DecisionTreeClassifier` (`max_depth=8`, `min_samples_leaf=6`)
6. Evaluates on the held-out test set: accuracy, precision, recall, F1, confusion matrix
7. Saves the trained pipeline to `models/traffic_model.pkl` and the metrics to
   `models/metrics.json`
8. Saves a simplified (first-3-levels-only) tree diagram to `frontend/public/decision_tree.png`

**Result with the included dataset: ~76% accuracy** (macro F1 ~0.76). The model is
essentially perfect at telling Low apart from High, and least confident right at the
Low/Medium and Medium/High boundaries — which is realistic, and worth pointing out
during a review as evidence the dataset isn't artificially "too easy".

## 8. Academic Explanation (Q&A)

Plain-English answers you can use directly when explaining this project to faculty.

**What is Artificial Intelligence (AI)?**
Building software that performs tasks which normally need human judgment — here, judging
how congested a road is likely to be.

**What is Machine Learning (ML)?**
A branch of AI where, instead of hand-writing rules, a program *learns* rules from
examples (data). This project's Decision Tree learned its rules from `traffic_data.csv`.

**What is supervised learning?**
Learning from labeled examples — each row in the dataset has both the inputs (vehicle
count, hour, weather, ...) and the correct answer (`traffic_level`). The model learns the
mapping between them.

**What is classification?**
A supervised learning task where the output is one of a fixed set of categories, rather
than a number. Here, the categories are Low / Medium / High.

**What is a Decision Tree?**
A model shaped like a flowchart of yes/no questions about the features. You start at the
top (the root) and follow the branch that matches your data at each question until you
reach a leaf, which gives the final answer.

**Why was Decision Tree selected?**
It's easy to visualize and explain (see the diagram on the Model Performance page), needs
little data preprocessing, and naturally handles a mix of numeric and categorical
features — a good fit for a project that needs to be explainable in a review.

**What is a feature?**
One input column the model uses to predict — here: `vehicle_count`, `hour`,
`day_of_week`, `weather`, `location`, `previous_traffic`.

**What is the target variable?**
The column the model is trying to predict: `traffic_level`.

**What is training data?**
The 80% of the dataset (2,400 of 3,000 records) the model actually learns its rules
from.

**What is testing data?**
The remaining 20% (600 records) the model never sees during training — used only to
check how well it generalizes to new data.

**What is train-test split?**
The process of dividing one dataset into a training portion and a testing portion (done
in `train_model.py` with `train_test_split(..., test_size=0.2)`), so evaluation reflects
performance on unseen data rather than data the model has memorized.

**What is a prediction?**
The model's output for one new, unlabeled input — e.g. given today's conditions, the
predicted `traffic_level`.

**What is accuracy?**
The percentage of test-set predictions the model got exactly right. This project's model
scores around 76%.

**What is a confusion matrix?**
A table comparing actual vs. predicted classes, so you can see not just how often the
model is right, but exactly *which* classes it confuses (see the Model Performance page —
this model mostly confuses Medium with its neighbors, not Low with High).

**How does the Decision Tree make a prediction?**
It answers the questions stored at each node (e.g. "vehicle count ≤ 190.5?") in order,
follows the True/False branch each time matches the input, and returns the class stored
at the leaf it lands on.

**Where exactly is AI used in this project?**
In one place, specifically: the `DecisionTreeClassifier` inside `train_model.py` /
`models/traffic_model.pkl`, which the Flask `/predict` endpoint calls. Everything else
(the React UI, the Flask routes, SQLite history) is standard web development that
surrounds and serves that one ML component.

## 9. Troubleshooting

| Problem | Fix |
|---|---|
| Sidebar shows "Backend unreachable" | Make sure `python app.py` is running in a separate terminal on port 5000. |
| `/predict` returns 503 "Model not found" | Run `python train_model.py` inside `backend/` (with the venv active), then restart `python app.py`. |
| `pip install` fails | Make sure you activated the virtual environment first (`source venv/bin/activate`). |
| Frontend can't reach a backend on a different host/port | Create `frontend/.env` with `VITE_API_URL=http://your-host:5000`, then restart `npm run dev`. |
| Port 3000 or 5000 already in use | Stop whatever else is using that port, or change the port in `vite.config.js` (frontend) / the `app.run(port=...)` call (backend). |
